Ownership

What each point is for

The role is a constraint. It is not a claim that every service currently obeys it.

Homelab

Owned production and durable state.

Stateful/private Docker services, storage, backups, Homelab API, and diagnostics.

Not: public edge policy or Mac mini worktrees.

OCI

External 24/7 runtime capacity.

Small public, stateless, loss-tolerant, unattended workloads that fit the 2 vCPU / 12 GB / 200 GB envelope.

Not: durable-data authority or required control plane.

Mac mini

Primary development host.

Interactive source work, tests, native macOS runtimes, and explicit previews.

Not: automatic production fallback.

Ubuntu laptop

Future optional closet node.

Ethernet and power when possible; possible Pi-hole, monitoring, and low-risk workers after commissioning.

Not: UPS, current dependency, or data authority.

Cloudflare

Public edge.

Public DNS, TLS, proxy/WAF, and reviewed tunnel routing to one declared origin.

Not: private mesh membership or placement authority.

Tailscale

Private connection plane.

Encrypted operator access and explicit host-to-host paths between named nodes.

Not: public Internet ingress.

MacBook Air

Personal access node.

Local operator tools and Tailscale access.

Not: persistent production state.

Work MacBook Pro

Restricted access client.

Approved terminal/SSH access to other machines.

Not: Tailscale, local runtimes, or persistent state.

Placement logic

Hard gates before convenience

Use decisive gates first. Use softer trade-offs only after a workload passes the gate.

  1. Durable, private, or storage-heavy? Put it on Homelab.
  2. Native macOS or interactive development? Keep it on the Mac mini.
  3. Public, stateless, loss-tolerant, and resource-fitting? OCI is eligible, pending route and recovery proof.
  4. Future laptop? It is ineligible until commissioned with verified boot, network, Tailscale/SSH, and remote recovery.
  5. No decisive match? Default to Homelab or classify first.

The default is safety, not movement.

If a workload cannot name its data authority, backup boundary, public route, resource budget, and recovery path, it does not move to OCI.

Decision queue

What happens next

The order protects the durable system while reducing OCI noise and management burden.

01

Dada cutover

Prove Homelab backup/restore, reconcile the service unit, map Cloudflare, then test public cutover and rollback.

02

OCI classification

Assign each app, gateway, runner, timer, cron job, and checkout an owner and disposition.

03

Replace repo sync

Use selected deployment paths. Never let a dirty or diverged worktree become a self-healing target.

04

Commission laptop later

Bring it online as optional auxiliary infrastructure only after remote recovery and power/network behavior are proven.
